# SDFF 格式规格

DCS 操作站流程图 `.pic` 文件的二进制格式。**逆向所得，非官方文档**——厂商
未公开规格，本文所有结论来自对 82 个真实文件的分析与全量解析验证。

验证状态：82/82 文件解析成功，无未知类型码、无残留字节。

---

## 1. 整体结构

```
┌─────────────────────────────┐ 0x00
│ Header (0x40)               │  'SDFF' + 流数量 + 创建时间 + GUID
├─────────────────────────────┤ 0x40
│ 目录项 0  (0x80)            │  名称 / 偏移 / 压缩标志 / 原始长度
│ 目录项 1  (0x80)            │
│ …                           │
├─────────────────────────────┤
│ (对齐填充至 0x1000)         │
├─────────────────────────────┤
│ 流负载 0                    │  u32 原始长度 + zlib 流
│ 流负载 1                    │
│ …                           │
└─────────────────────────────┘
```

流负载按目录项的 `offset` 定位，**不保证紧邻**，也不保证顺序与目录一致。
求某个流的压缩后长度要用「下一个更大的 offset（或文件尾）减去本 offset」。
实测所有文件里首个流固定落在 `0x1000`。

## 2. Header（0x40 字节）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0x00 | char[4] | 魔数 `SDFF` |
| 0x04 | u32 | 恒 0（用途未知） |
| 0x08 | u32 | 流数量，实测恒为 5 |
| 0x0C | u32 | 恒 0 |
| 0x10 | u64 | Windows FILETIME，文件创建/保存时间 |
| 0x18 | byte[16] | GUID，同一模板派生的文件共享此值 |
| 0x28 | byte[24] | 恒 0 |

## 3. 目录项（每条 0x80 字节）

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0x00 | UTF-16LE[0x40] | 流名，NUL 填充 |
| +0x40 | byte[0x10] | 恒 0 |
| +0x50 | u64 | 流负载在文件中的偏移 |
| +0x58 | u64 | 压缩标志，`1` = zlib，实测恒为 1 |
| +0x60 | u64 | **解压后**长度 |
| +0x68 | byte[0x18] | 恒 0 |

五个流固定为：`DocInfo`、`PageInfo`、`Shape`、`Tag`、`Text`。

## 4. 流负载

```
u32  原始长度（与目录项 +0x60 重复，可用于校验）
...  zlib 流（标准 78 9C 头，无自定义封装）
```

> 坑：直接对 `data[offset:]` 做 `zlib.decompress` 会失败——**必须跳过前 4 字节**。

## 5. 属性树（解压后的内容）

解压结果不是 XML 也不是自定义二进制布局，而是一棵**带类型标签的属性树**，
所有五个流共用同一套编码。

```
stream := u32 总长度 | record* | 0x00
record := u8 类型 | 名称(以 NUL 结尾的 GBK 字符串) | 值
```

字符串一律 **GBK**（简体中文 Windows 程序），不是 UTF-8 也不是 UTF-16。

### 类型码

| 码 | 类型 | 值编码 |
|---|---|---|
| `0x01` | double | 8 字节 IEEE754 小端 |
| `0x02` | 字符串 | `u32 字节数` + 该字节数的 GBK 数据（**含结尾 NUL**，计入长度） |
| `0x03` | 容器 | 见下 |
| `0x04` | 容器 | 见下，与 `0x03` 编码相同 |
| `0x05` | 字节数组 | `u32 字节数` + **1 字节 flag** + 该字节数的裸数据 |
| `0x08` | byte / bool | 1 字节 |
| `0x10` | int32 | 4 字节小端有符号 |
| `0x00` | — | 容器/流的终止符，不是类型 |

`0x03` 与 `0x04` 在实测数据里语义上没有区别，编码完全一致，按同一种处理即可。

### 容器编码（最容易踩错的地方）

```
u8 类型(0x03|0x04) | 名称 | u32 size | 子 record* | 0x00
                              ↑
                    size 从这个长度字段自身起算，
                    一直算到容器末尾的 0x00 终止符（含）
```

也就是说：

```python
container_end = position_of_size_field + size   # 指向终止符之后
children_end  = container_end - 1               # 终止符本身不属于子记录
```

**踩过的坑**：把 `size` 当成「子记录字节数」会整棵树错位，而且错位往往要到几百
字节之后才表现为「未知类型码」，不容易定位到真正的起因。

### 数组编码

`0x05` 的长度字段之后有 **1 个额外的 flag 字节**（实测恒为 0），再是裸数据。
漏掉这个字节会让后续解析偏移 1 字节。

数组的元素类型随宿主字段而定，格式本身不携带该信息：

| 字段 | 内容 |
|---|---|
| `clsid` | 16 字节 GUID，标识图元类型 |
| `arPoint` / `arPointRotate` | int32 坐标对 `(x, y)` 序列 |
| `curveX` / `curveY` | float32 贝塞尔控制参数 |
| `logFont` | 60 字节 Win32 `LOGFONT` 结构 |

### 数组 vs 列表

键名全是十进制数字（`"0"`、`"1"`、`"2"`…）的容器表示**有序列表**；其余是字典。
`lstShape`、`texts`、`tag`、`layerNames` 都是前者。

## 6. 各流内容

### DocInfo

```python
{'version': 12800, 'fileType': 0, 'templateName': ''}
```

`version` 实测恒为 12800（`0x3200`），组态软件版本标识。

### PageInfo

画布与页面属性。关键字段：

| 字段 | 含义 |
|---|---|
| `docWidth` / `docHeight` | 画布尺寸，实测 1920×960 |
| `strTemplateName` | 继承的模板文件名，如 `主产线背景模版.pic` |
| `layerNames` | 图层名列表（`图层 0` … `图层 3`） |
| `nRefreshTimer` | 刷新周期毫秒，实测 500 |
| `lastID` | 图元 ID 分配水位 |
| `strPassword` / `bPasswdEnable` | 页面口令保护 |

### Shape

`lstShape` 是图元树。组合图元带 `shapes` 子列表，**可嵌套**——只遍历顶层会漏图元。

所有图元共有：`clsid`（类型 GUID）、`name`、`id`、`bVisible`、`layer`、`nSecurity`。

几何用两套字段，按图元类型二选一：
- 线性图元：`startX` / `startY` / `endX` / `endY`
- 容器类图元：`left` / `top` / `right` / `bottom`

**`DataLink` 图元是位号的主要载体**，携带 `strDLTag`（位号）+ 坐标 + 显示格式
（`nWholeDigits` / `bDisplayUnit` / `nFormat`）+ 报警显示方式（`nAlarmShowType`）。
另有少量图元用 `strTag` 字段，两个都要查。

### Tag

页面级位号登记表，两组：

| 组 | 含义 |
|---|---|
| `tag` | 数值显示绑定的位号 |
| `ani` | 动画绑定的位号（阀门开关、设备启停、故障闪烁等） |

**这一组比遍历 `Shape` 更全**——动画绑定不一定挂在带 `strDLTag` 的图元上。

位号可带引用后缀：`P1_LS100103A01_PV.PV`、`P1_HV100104A02_KFK.ERR`。
join 点表时要先按 `.` 切掉后缀。

`ani` 里还可能出现**表达式**而非纯位号，例如
`P1_2_M100601F_AOL OR P1_2_UF100601B_A`、`P1_3_HV100701A_K + 2 * P1_3_HV100701A_G`。
这类无法直接对点表——占实测 12,012 个位号里的 202 个（1.7%）。

### Text

`texts` 是页面上全部静态中文标签的扁平列表（`补水阀`、`雾化器`、`1#加料泵`…）。
只有文本内容，不含坐标——**要拿坐标必须回 `Shape` 流找带 `content` 的图元**。

## 7. 已知未解之处

规格已够用于全量解析与位号抽取，但以下部分未继续深挖（当前需求用不上）：

- `clsid` GUID 到图元类型名的映射表（只统计了分布，未逐一命名）
- `logFont` 之外的部分 `0x05` 数组的字段级语义
- `DocInfo.version = 12800` 对应的组态软件版本号
- Header 里两处恒 0 的 u32 与 GUID 的确切派生规则
- 管道图元的连接关系是否显式存储（当前只确认了几何走向，拓扑需要从坐标推）
